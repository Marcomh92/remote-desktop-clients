# Android Data Layer

## MANDATORY FIRST ACTIONS

Before creating data layer classes:
1. Define the domain model in `domain/model/` first
2. Define the repository interface in `domain/repository/`
3. Then create implementation in `data/repository/`

Skip = violates dependency rule (Domain must not depend on Data).

## Repository Pattern

Repositories use the `Impl` suffix and are injected via Hilt.

### Dual-Method Retrieval Pattern

**Every get operation MUST provide two methods:**
1. A `suspend` method returning the value directly (one-shot)
2. A `Flow` method returning the value as a reactive stream

The Flow method name is the suspend method name with `Flow` appended:

```kotlin
// domain/repository/NotesRepository.kt
interface NotesRepository {
    // Write operations
    suspend fun insert(note: Note)
    suspend fun update(note: Note)
    suspend fun delete(noteId: String)

    // Dual-method retrieval: suspend + Flow
    suspend fun getByLocalId(localId: String, includeDeletes: Boolean = false): Note?
    fun getByLocalIdFlow(localId: String, includeDeletes: Boolean = false): Flow<Note?>

    suspend fun getByCategoryId(categoryId: String, includeDeletes: Boolean): List<Note>
    fun getByCategoryIdFlow(categoryId: String, includeDeletes: Boolean): Flow<List<Note>>

    suspend fun getAll(includeDeletes: Boolean = false): List<Note>
    fun getAllFlow(includeDeletes: Boolean = false): Flow<List<Note>>
}

// data/repository/NotesRepositoryImpl.kt
class NotesRepositoryImpl @Inject constructor(
    private val noteDao: NoteDao,
    private val noteDomainMapper: NoteDomainMapper
) : NotesRepository {

    override suspend fun getByLocalId(
        localId: String,
        includeDeletes: Boolean
    ): Note? = withContext(Dispatchers.IO) {
        noteDao.getByLocalId(localId, includeDeletes)
            ?.let { noteDomainMapper.toDomain(it) }
    }

    override fun getByLocalIdFlow(
        localId: String,
        includeDeletes: Boolean
    ): Flow<Note?> {
        return noteDao.getByLocalIdFlow(localId, includeDeletes)
            .map { entity -> entity?.let { noteDomainMapper.toDomain(it) } }
            .flowOn(Dispatchers.IO)
    }

    override suspend fun getByCategoryId(
        categoryId: String,
        includeDeletes: Boolean
    ): List<Note> = withContext(Dispatchers.IO) {
        noteDao.getByCategoryId(categoryId, includeDeletes)
            .map { noteDomainMapper.toDomain(it) }
    }

    override fun getByCategoryIdFlow(
        categoryId: String,
        includeDeletes: Boolean
    ): Flow<List<Note>> {
        return noteDao.getByCategoryIdFlow(categoryId, includeDeletes)
            .map { list -> list.map { noteDomainMapper.toDomain(it) } }
            .flowOn(Dispatchers.IO)
    }

    override suspend fun insert(note: Note) = withContext(Dispatchers.IO) {
        noteDao.insert(noteDomainMapper.toEntity(note))
    }
}
```

**Rules:**
- The Data Layer handles ALL dispatcher switching. Domain and Presentation never specify `Dispatchers.IO`.
- Every read operation MUST expose both a `suspend` one-shot and a `Flow` reactive variant.
- Flow methods are named `[suspendMethodName]Flow` (e.g., `getAll` → `getAllFlow`).

## Room Entities

Entities use `localId` as locally-generated `@PrimaryKey` and `remoteId` as server-generated id (nullable as this will be generated by the server after being synced):

```kotlin
@Entity(tableName = "notes")
data class NoteEntity(
    @PrimaryKey
    val localId: String,
    val remoteId: String? = null,

    val title: String,
    val body: String,
    val isDeleted: Boolean = false,
    // ...
)
```

This supports the **Dual-Identity System** (offline creation with local IDs, server sync with remote IDs).

## DAO Pattern

DAOs are interfaces with `@Dao` annotation. Follow the same dual-method pattern as repositories:

```kotlin
@Dao
interface NoteDao {
    // One-shot reads
    @Query("SELECT * FROM notes WHERE local_id = :id AND is_deleted = :includeDeletes")
    suspend fun getByLocalId(id: String, includeDeletes: Boolean): NoteEntity?

    @Query("SELECT * FROM notes WHERE category_id = :categoryId AND is_deleted = :includeDeletes")
    suspend fun getByCategoryId(categoryId: String, includeDeletes: Boolean): List<NoteEntity>

    // Flow reads
    @Query("SELECT * FROM notes WHERE local_id = :id AND is_deleted = :includeDeletes")
    fun getByLocalIdFlow(id: String, includeDeletes: Boolean): Flow<NoteEntity?>

    @Query("SELECT * FROM notes WHERE category_id = :categoryId AND is_deleted = :includeDeletes")
    fun getByCategoryIdFlow(categoryId: String, includeDeletes: Boolean): Flow<List<NoteEntity>>

    // Write operations
    @Upsert
    suspend fun upsertAll(notes: List<NoteEntity>)
}
```

## Retrofit API

APIs define suspend functions returning `Response<T>`:

```kotlin
interface NoteApi {
    @GET("notes")
    suspend fun getNotes(): Response<List<NoteDto>>

    @POST("notes")
    suspend fun createNote(@Body dto: NoteDto): Response<NoteDto>

    @PUT("notes/{id}")
    suspend fun updateNote(
        @Path("id") id: String,
        @Body dto: NoteDto
    ): Response<NoteDto>
}
```

## Mappers

Mappers are **injectable classes** (not extension functions) that convert between layers:

```kotlin
// data/local/mappers/NoteDomainMapper.kt
class NoteDomainMapper @Inject constructor() {
    fun toDomain(entity: NoteEntity, category: CategoryEntity?, task: ActiveTask?): Note {
        return Note(
            id = entity.localId,
            remoteId = entity.remoteId,
            title = entity.title,
            // ...
        )
    }

    fun toEntity(note: Note, categoryId: String?): NoteEntity {
        return NoteEntity(
            localId = note.id,
            remoteId = note.remoteId,
            title = note.title,
            // ...
        )
    }
}

// data/remote/mappers/NoteApiMapper.kt
class NoteApiMapper @Inject constructor() {
    fun toDto(note: Note): NoteDto {
        return NoteDto(
            id = note.remoteId ?: note.id,
            title = note.title,
            // ...
        )
    }
}
```

## Remote Data Source

Remote data sources return `Result<T>` for error handling:

```kotlin
class NoteRemoteDataSourceImpl @Inject constructor(
    private val noteApi: NoteApi
) : NoteRemoteDataSource {
    override suspend fun fetchNotes(): Result<List<NoteDto>> {
        return runCatching {
            val response = noteApi.getNotes()
            if (response.isSuccessful) {
                response.body() ?: emptyList()
            } else {
                throw IOException("HTTP ${response.code()}")
            }
        }
    }
}
```

**Note:** `@Inject` usage varies. `CategoryRepositoryImpl` uses `@Inject constructor`, but `NotesRepositoryImpl` does NOT (dependencies are provided manually in `RepositoryModule`). Follow the pattern of the repository you're working near.

## Offline-First

The local database is the single source of truth:

1. UI observes local DB via `Flow`
2. User actions update local DB immediately (optimistic)
3. Background sync propagates changes to server
4. ViewModel NEVER reads from network directly

## Naming Conventions

| Component            | Convention                          | Example |
|----------------------|-------------------------------------|---|
| Repository interface | `NotesRepository`                   | `domain/repository/NotesRepository.kt` |
| Repository impl      | `NotesRepositoryImpl`               | `data/repository/NotesRepositoryImpl.kt` |
| DAO                  | `NoteDao`                           | `data/local/database/dao/NoteDao.kt` |
| Entity               | `NoteEntity`                        | `data/local/entity/note/NoteEntity.kt` |
| Request DTO          | `NoteRequestDTO`                    | `data/remote/dto/note/NoteRequestDTO.kt` |
| Response DTO         | `NoteResponseDTO`                   | `data/remote/dto/note/NoteResponseDTO.kt` |
| Mapper               | `NoteDomainMapper`, `NoteApiMapper` | In `data/local/mappers/`, `data/remote/mappers/` |
